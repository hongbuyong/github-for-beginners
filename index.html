6단계원본을 지키면서 함께 고치는 법

재생을 누르면 브랜치가 갈라지고 다시 합쳐지는 과정을 순서대로 그려요.

용어 한 줄 정리

  • 커밋 git commit

    지금 상태를 메모와 함께 저장해요. 게임의 세이브 포인트와 같아요.

  • 푸시 git push

    내 컴퓨터의 커밋을 GitHub에 올려요.

  • 풀 git pull

    GitHub에 올라온 최신 내용을 내 컴퓨터로 받아와요.

  • 브랜치 git switch -c

    원본은 그대로 두고 따로 작업할 갈래를 만들어요.

  • PR Pull Request

    "내 브랜치를 원본에 합쳐 주세요"라는 요청이에요. 여기서 리뷰와 코멘트를 주고받아요.

  • 머지 Merge

    리뷰를 통과한 브랜치를 원본(main)에 합쳐요.

  • 배포 Deploy

    main의 코드를 운영 서버에 올려서 고객 화면을 바꿔요. 보통 main이 바뀌면 자동으로 실행돼요.

  • 테스트 서버 Staging

    운영에 올리기 전 test.shop.com 같은 연습용 서버에서 먼저 확인하는 곳이에요. 팀마다 있을 수도, 없을 수도 있어요.

자주 헷갈리는 것들

Git과 GitHub

Git은 내 컴퓨터에서 버전을 기록하는 프로그램이고, GitHub는 그 기록을 올려 두고 함께 보는 웹사이트예요.

커밋과 푸시

커밋은 내 컴퓨터에만 저장해요. 푸시를 해야 다른 사람도 내 변경을 볼 수 있어요.

푸시하면 서비스가 바뀐다?

아니에요. 푸시는 GitHub 창고에 올리는 것뿐이에요. 고객 화면은 main에 머지된 뒤 배포가 돼야 바뀌어요.

내 화면에서 되면 다 된다?

내 노트북(localhost)과 운영 서버는 설정과 데이터가 달라요. 그래서 리뷰와 테스트를 거쳐서 올려요.

풀을 받으면 고객 화면도 맞춰진다?

풀은 내 노트북의 코드만 최신으로 바꿔요. 고객 화면과는 상관없어요.
