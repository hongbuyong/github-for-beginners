# GitHub for Beginners · 깃허브 작업 흐름

커밋, 푸시, PR, 머지, 배포, 그리고 충돌 해결까지.
"나"와 "팀원"이 `login.html` 한 파일을 주고받는 장면을 따라가며 깃허브가 어떻게 돌아가는지 보여 주는 한국어 입문 자료예요.

## 무엇을 보여 주나요

장면에는 네 곳이 나와요.

| 장소 | 하는 일 |
|---|---|
| 내 노트북 / 팀원 노트북 | 각자 고치고 `localhost`에서 화면을 확인하는 곳 |
| GitHub | 코드를 보관하고 리뷰하고 합치는 곳 |
| 운영 서버 | 고객이 실제로 보는 `shop.com`이 돌아가는 곳 |

20단계를 다섯 부분으로 나눠 보여 줘요.

1. **내 작업 보내기**: 고치기 → 커밋 → 푸시 → PR
2. **합치고 고객에게 배포하기**: 리뷰 → 머지 → 자동 배포 → 풀
3. **팀원 작업 보내기**: 팀원이 커밋 → 푸시 → PR
4. **내가 합치고 받기**: 리뷰·머지 → 풀
5. **같은 줄을 동시에 고치면**: 충돌이 생기고, 사람이 골라서 해결하기까지

단계마다 아래 내용이 함께 나와요.

- 그 순간의 실제 화면(편집기, 터미널, GitHub PR 페이지, GitHub Actions 기록)
- "지금 각자 가진 login.html" 현황판. 나, GitHub, 팀원, 고객 화면이 각각 어떤 버전인지 보여 줘요.

## 사용법

- 웹: 위 주소를 열면 돼요. 데스크톱에서는 자동으로 재생되고, 버튼으로 멈추거나 단계를 넘길 수 있어요.
- 휴대폰: 장면이 화면 위에 고정되고, 장면을 옆으로 밀어서 넘겨요. 아래 탭에서 설명, 버전 현황판, 화면 속 내용을 골라 볼 수 있어요.
- 소리: 재생 버튼 옆 스피커 버튼으로 효과음을 켤 수 있어요. 기본은 꺼져 있어요.
- 내 컴퓨터에서 보기: 저장소를 내려받아 `index.html`을 브라우저로 열면 돼요. 설치할 것이 없어요.

## 개인정보와 보안

- 이 페이지는 **외부 서버에 아무 요청도 보내지 않아요.** 글꼴, 스크립트, 이미지 모두 파일 안에 들어 있거나 기기에 있는 것을 써요.
- 분석 도구, 쿠키, 광고가 없어요.
- 브라우저 저장소(`localStorage`)에는 두 가지만 저장해요. 마지막으로 고른 탭(`gh-flow-tab`)과 효과음 켜짐 여부(`gh-flow-sound`)예요. 이 값은 내 브라우저에만 남아요.
- 페이지에 콘텐츠 보안 정책(CSP)을 걸어 두었어요. 파일에 들어 있는 스크립트 외에는 실행되지 않고, 외부 연결도 막혀 있어요.

보안 문제를 발견하면 [SECURITY.md](SECURITY.md)를 참고해 주세요.

## 함께 고치기

오타, 더 쉬운 설명, 새로운 장면 아이디어 모두 환영해요. Issue나 Pull Request로 알려 주세요.

### main 브랜치 보호 규칙

`main` 브랜치에는 아래 규칙이 걸려 있어요. 예외는 없어서 관리자도 똑같이 적용돼요.

- **강제 푸시 금지**: `git push --force`로 기존 기록을 덮어쓸 수 없어요. 고칠 게 있으면 새 커밋을 더해 주세요.
- **브랜치 삭제 금지**: `main` 브랜치를 지울 수 없어요.

평소처럼 커밋을 쌓아 올리는 푸시와 PR 머지는 그대로 할 수 있어요. 외부 기여자는 저장소를 fork한 뒤 Pull Request를 보내 주세요.

`index.html` 안의 스크립트를 고치면 CSP 해시도 바꿔야 해요. 바꾸지 않으면 스크립트가 실행되지 않아요. 아래 명령으로 해시가 맞는지 확인할 수 있고, 맞지 않으면 새 해시를 알려 줘요.

```bash
python scripts/check_csp_hash.py
```

Pull Request를 올리면 GitHub Actions가 같은 검사를 자동으로 돌려요. 해시가 맞지 않으면 PR에 실패 표시가 붙어요.
